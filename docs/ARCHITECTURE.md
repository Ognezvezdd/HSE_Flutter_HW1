# Как читать проект

Эта памятка подготовлена агентом для разбора реализации. Она не заменяет
самостоятельный авторский раздел 7 README.

| Файл | Ответственность |
| --- | --- |
| `lib/main.dart` | Точка входа, запуск приложения |
| `lib/app.dart` | Создание API/хранилища, настройка приложения и освобождение HTTP-клиента |
| `lib/app_config.dart` | Параметры сборки и проверка конфигурации |
| `lib/app_theme.dart` | Единая тема интерфейса |
| `lib/models/cat.dart`, `breed.dart`, `json_fields.dart` | Модели и безопасное чтение полей JSON |
| `lib/models/feed_snapshot.dart` | Снимок сохраняемого состояния |
| `lib/services/cat_api.dart` | HTTP, таймауты, авторизация, разбор ответа, кеш каталога |
| `lib/services/feed_store.dart` | Чтение и запись единого снимка в локальное хранилище |
| `lib/screens/home_screen.dart` | Фазы ленты, счётчик, голосование, повтор, восстановление, вкладки |
| `lib/screens/breeds_screen.dart` | Каталог, загрузка/ошибка, сохранение прокрутки |
| `lib/screens/breed_details_screen.dart` | Детали переданной породы, для кота — с переданным фото |
| `lib/widgets/cat_card.dart`, `cat_actions.dart` | Карточка и закреплённые кнопки; действия передаются callback |
| `lib/widgets/breed_information.dart` | Общий блок сведений о породе |
| `lib/widgets/status_panel.dart` | Общий вид загрузок, сообщений и повтора |

Импорт делает определения другого файла доступными. Реальный объект передаётся
через конструктор: например, `HomeScreen` получает уже созданные API и хранилище.
Виджет описывает интерфейс по текущему состоянию; `setState` просит Flutter
пересобрать нужную часть дерева. Сам по себе повторный `build` не означает новый
HTTP-запрос: запросы запускаются обработчиками и инициализацией.

## Путь одного лайка

1. Кнопка и свайп вызывают один путь голосования в `HomeScreen`.
2. Обработчик проверяет готовность и принадлежность действия текущей карточке.
3. Фаза меняется, повторное действие блокируется. Формируется снимок с новым
   счётчиком и без уже обработанного кота.
4. Снимок записывается. После успеха запрашиваются следующие данные и фото;
   новый кот сохраняется, затем карточка становится готовой.
5. Ошибка переводит экран в подходящее состояние повтора. Повтор запроса
   не возвращается к шагу начисления лайка.

В деталях используется переданная модель, а не новый поиск. Вкладки сохраняются
в `IndexedStack`; хранилище нужно для полного перезапуска, а не для каждого `build`.

## Вопросы для самостоятельного разбора

- Где находится единственный изменяемый счётчик и кто вправе его менять?
- Почему новый снимок сохраняется до поиска следующего кота?
- Чем повтор фотографии отличается от повтора поиска?
- Почему Back и переключение вкладки не должны вызывать новый поиск?
- Что защищает от повторного действия и обновления удалённого `State`?

Найдите ответы в коде и проверьте их запуском. Затем самостоятельно напишите
свои 5–10 предложений для README: условие требует именно авторское объяснение.
