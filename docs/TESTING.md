# Проверка поведения и ошибок

Сценарии проверяют голосование, навигацию, сохранение и восстановление после
контролируемых ошибок. Результаты — в [журнале](QUALITY_GATES.md).

## Ручная проверка

| Сценарий | Действие и ожидаемый результат |
| --- | --- |
| Чистая установка | Установить APK на отдельный пустой AVD: настоящий кот, 0 лайков |
| Голосование | Кнопка/свайп вправо дают +1, пропуск/влево — без изменения; один переход на действие |
| Быстрые действия | Несколько нажатий или свайп вместе с нажатием: один голос, один переход |
| Детали | То же фото/порода; Back сохраняет карточку и счётчик; свайп не открывает детали |
| Каталог | Выбрать породу после прокрутки; Back сохраняет позицию, вкладки — кота и лайки |
| Перезапуск / Web refresh | Тот же кот и счётчик; при перезапуске во время запроса принятый голос остаётся |
| Нет сети | Отключить и Wi-Fi, и мобильные данные Android, затем поставить лайк: ошибка и N+1. После восстановления сети повтор даёт кота и всё ещё N+1 |
| Неверный ключ | Полный запуск с `--dart-define=CAT_API_KEY=invalid-for-testing`: явная ошибка ключа без повтора |
| Нет ключа | Полный запуск без параметров: инструкция подключения, без карточки и запросов |
| Размеры | 320×568 и шрифт ×2: обе кнопки доступны и неподвижны при прокрутке, детали читаются |
| Иконка | Свой знак виден в маске launcher и открывает приложение |

Готовая фотография может оставаться в памяти без сети. Для проверки ошибки
нужен новый запрос. После включения радио дождитесь подключения Android и нажмите
«Повторить». Не очищайте рабочие данные ради теста: для свежей установки нужен
отдельный AVD. Другой origin/порт Web означает отдельное хранилище.

## Командная строка

Из корня проекта; ID подставляются из `flutter emulators` / `flutter devices`:

```sh
flutter doctor -v
flutter emulators --launch Pixel_8
flutter run -d emulator-5554 --release --dart-define-from-file=config.json
flutter build apk --release --dart-define-from-file=config.json
flutter test
```

Смена `dart-define` требует Stop → Run. Личный `config.json` для негативных
проверок не меняйте. Для Gradle проекта проверен полный JDK 21 с `jlink`;
выбранную Java показывает `flutter doctor -v`.

## Контролируемые ошибки

`test/cat_api_test.dart` / `breeds_api_test.dart` используют `MockClient` для
HTTP 401/403/429/500, пустого/неверного JSON, отсутствия породы и таймаута.
`home_screen_test.dart` проверяет повтор, сбой изображения/хранилища, сохранение
и двойные действия; `navigation_test.dart` — фото, Back, прокрутку и свайп/детали.
Данные и изображения тестов не подменяют production-данные.

Нативный release проверяется также через временный HTTPS API. Сервер умеет
задерживать ответы, ломать JSON и фото, возвращать нужные HTTP-коды; проверяется
и количество запросов. Пять групп (`feed`, `errors`, `catalog`, `lifecycle`,
`network`) запускаются последовательно на отдельном AVD.
Полные команды — в [tool/acceptance](../tool/acceptance/README.md).
Тестовая сборка не публикуется; после проверки возвращается обычный APK.
