# Как проверять ошибки

Проверяем наблюдаемое поведение и сохранение состояния. Если после первого
действия карточка сразу исчезает и повторно нажать нельзя — это ожидаемая защита.
Не нужно добиваться, чтобы приложение обязательно сломалось.

## Android из командной строки

Итоговая приёмка выполняется на отдельном временном AVD, чтобы проверить свежую
установку без удаления данных рабочего Pixel 8. Для управляемых сбоев используется
отдельный сервер тестовых ответов и тестовый ключ: обычная release-сборка продолжает
работать с TheCatAPI. Сервер доступен приложению по HTTPS с действительным
сертификатом; проверка TLS и исходники приложения для этого не ослабляются.
Проверяем запросы и их количество, таймаут, HTTP 401/403/429/500, пустой/неверный
JSON, отсутствие породы, сбой фото, повтор, каталог, быстрые действия и уход с экрана.
Дополнительно собираются варианты без личного config-файла и без ключа.
Воспроизводимые инструменты и команды: [tool/acceptance](../tool/acceptance/README.md).

Команды выполняются из каталога с `pubspec.yaml`:

```sh
flutter doctor -v
flutter emulators
flutter emulators --launch Pixel_8
flutter devices
flutter run -d emulator-5554 --release --dart-define-from-file=config.json
```

`Pixel_8` — ID настроенного AVD, `emulator-5554` — ID запущенного устройства;
подставьте значения из вывода команд, если они отличаются. Уже работающий
эмулятор повторно запускать не нужно. Для обычной разработки уберите `--release`.
APK для отдельной установки:

```sh
flutter build apk --release --dart-define-from-file=config.json
```

Результат: `build/app/outputs/flutter-apk/app-release.apk`. Для Gradle 9.3.1
использован полный JDK 21 с `jlink`; выбранный путь показывает `flutter doctor -v`.
Настройка Flutter: `flutter config --jdk-dir=<путь к полному JDK>`.

При проверке сети на эмуляторе отключайте и Wi-Fi, и мобильные данные внутри
Android. Дождитесь ошибки или установленного таймаута; затем восстановите оба
подключения и нажмите «Повторить». Сеть компьютера отключать не требуется.
Перед сдачей отдельно пройдите свежую установку финального APK. Агент проверял
обновление существующей установки через `adb install -r`, сохранив данные автора.

## Вручную

Команды выполняются из каталога с `pubspec.yaml`. Для разных ключей нужен полный
перезапуск. Личный `config.json` для негативных проверок не меняем.

| Сценарий | Действия | Ожидаемый результат |
| --- | --- | --- |
| Неверный ключ | `flutter run -d macos --dart-define=CAT_API_KEY=invalid-for-testing` | «Ключ API не принят», инструкция исправить ключ и перезапустить; кнопки «Повторить» нет |
| Ключ отсутствует | `flutter run -d macos` без `--dart-define` и файла конфигурации | Инструкция подключения, карточки и заведомо неавторизованных запросов нет |
| Нет сети при запуске | Отключить Wi-Fi/остальные подключения и запустить с обычным `config.json` | Понятная ошибка и повтор; после восстановления сети повтор загружает карточку |
| Сеть потеряна после лайков | С действительным ключом получить несколько лайков, запомнить N, отключить сеть, поставить ещё один лайк | Счётчик N+1, затем ошибка. Вернуть сеть и повторить: следующий кот, счётчик по-прежнему N+1 |
| Быстрые действия | Быстро нажимать лайк несколько раз; отдельно повторить с пропуском и свайпами | Одна принятая карточка даёт не более одного лайка и одного перехода. Во время загрузки действий нет |
| Refresh / повторный запуск (R2) | Сделать несколько лайков, дождаться готовой карточки, запомнить число и кота, обновить страницу или закрыть и открыть приложение | Тот же счётчик, тот же ID кота, фотография и порода; новый случайный кот не запрашивается |
| Refresh во время запроса следующего кота | Поставить лайк и обновить страницу во время загрузки | Принятый лайк сохраняется, загружается следующий кот; обработанная карточка не возвращается |
| Детали кота и Back | Запомнить фото, породу и счётчик; нажать фото, прокрутить сведения, вернуться | То же фото в деталях; возврат сохраняет кота и лайки, не запрашивает случайного кота |
| Каталог и Back | Открыть «Породы», прокрутить список, открыть выбранную породу, вернуться | Описание и характеристики относятся к выбранной породе; список остаётся на прежней позиции |
| Смена вкладок | Переключить «Коты / Породы» несколько раз, в том числе во время загрузки | Кот, лайки и прокрутка сохраняются; переключение не начинает повторную загрузку |
| Каталог после ошибки кота | Загрузить каталог, отключить сеть, поставить лайк, после ошибки открыть «Породы» | Принятый лайк остаётся; загруженные породы и их детали доступны |
| Узкий экран | Уменьшить окно приложения, прокрутить карточку | Нет переполнения; обе кнопки достижимы, длинный текст не ломает экран |
| Закреплённые действия | На маленьком экране увеличить шрифт и прокручивать карточку | Кнопки лайка/пропуска остаются целиком видны и не двигаются вместе с карточкой; при необходимости располагаются вертикально |
| Иконка | Установить новый APK, найти «Кототиндер» в launcher и открыть его | Видна собственная иконка кота с сердечком; знак не обрезан маской; приложение запускается |

Уже загруженная фотография остаётся доступна без сети. Чтобы проверить ошибку,
после отключения сети нужно запустить новый запрос, например перейти к следующему
коту. Простое отключение Wi-Fi не должно само удалять готовую карточку.
Для сохранения между Web-запусками используем постоянный порт:
`flutter run -d chrome --web-port=7357 --dart-define-from-file=config.json`.
Другой host/порт, инкогнито или очистка данных сайта означают отдельное/пустое хранилище.

## Воспроизводимо через тесты

Серверу нельзя приказать вернуть 500 или пустой JSON. Для этих сценариев тесты
передают `MockClient` с заранее определённым ответом. Для сбоя фотографии они
передают некорректный `MemoryImage`. Это зависимости теста; приложение продолжает
использовать настоящий API и `NetworkImage`.

Все проверки:

```sh
flutter test
```

Точные проверки по одной:

```sh
flutter test test/home_screen_test.dart --plain-name "invalid key shows an explicit error without retry"
flutter test test/home_screen_test.dart --plain-name "double tap accepts one like; failed next request can be retried"
flutter test test/home_screen_test.dart --plain-name "photo retry keeps the same cat and does not refetch metadata"
flutter test test/cat_api_test.dart --plain-name "times out a request that never completes"
flutter test test/home_screen_test.dart --plain-name "restart restores the same cat and likes without another search"
flutter test test/home_screen_test.dart --plain-name "restart during next request keeps the like and consumes the old cat"
flutter test test/home_screen_test.dart --plain-name "failed vote save can be retried without adding a second like"
flutter test test/feed_store_test.dart
flutter test test/navigation_test.dart
flutter test test/breeds_api_test.dart
flutter test test/breed_model_test.dart
```

В тесте двойного лайка один обработчик вызывается дважды подряд до следующей
перерисовки. Проверяется, что счётчик вырос только на 1. Затем сервер намеренно
отвечает 503; обработчик повтора тоже вызывается дважды. Проверяется один новый
запрос кота без дополнительного лайка.

HTTP 401/403/429/500, пустой ответ, неверный JSON, кот без породы, отсутствие сети
и таймаут проверяются в `test/cat_api_test.dart`. В тесте таймаута ответ никогда
не завершается; предел ожидания сокращён только для этого теста. Так результат
не зависит от скорости настоящей сети.

В UI-тестах также проверяются исчезновение кнопки повтора при ошибке ключа,
повтор настоящего сбоя данных, сохранение лайка при отказе авторизации, ошибка
фото, свайпы, уход с экрана во время запроса и узкий экран с увеличенным текстом.
Они не заменяют ручной прогон APK на Android перед сдачей.

Каталог отдельно проверяется с пустым ответом, ошибкой сервера и повтором,
одновременными запросами и уходом с экрана до ответа. Тесты навигации проверяют
одну и ту же фотографию, неизменность счётчика, прокрутку списка, переключение
вкладок во время запроса и длинные детали на узком экране с увеличенным текстом.
Старое сохранение R2 без новых полей породы читается и дополняется по каталогу
без смены ID кота, URL фотографии или числа лайков.
UI-тесты используют тему приложения. Проверка 320×568 с текстом ×2 проверяет
границы и доступность обеих кнопок, неизменность их положения при прокрутке
карточки и работоспособность лайка после прокрутки.

## Запись ревью

В `QUALITY_GATES.md` записываем: commit, кто проверял, действия, фактический
результат, ожидаемый результат, исправление и его commit, повторную проверку.
Проверка агентом и подтверждение автором отмечаются отдельно.
Настоящий ключ не помещаем в журнал, команды отчёта и скриншоты.
