# Проверки и ревью

План объявлен до реализации. Статус «пройдено» ставится только после фактической
проверки; команды, commit, среда, результат и ограничения записываются в журнал.
Автотесты не обязательны; добавляем их при конкретной пользе для проверки поведения.

## Обязательные проверки

| ID | Проверка | Критерий |
| --- | --- | --- |
| G1 | `dart format --output=none --set-exit-if-changed .` | Форматирование не требует изменений |
| G2 | `flutter analyze` | Нет замечаний; подключён `flutter_lints` |
| G3 | `flutter build apk --release --dart-define=CAT_API_KEY=<локальный ключ> --dart-define=CAT_API_BASE_URL=https://api.thecatapi.com/v1` | Release APK собран; настоящий ключ не записан в журнал |
| G4 | Основные сценарии на Android | Свежая установка APK; лайки/пропуски кнопками и свайпами; несколько котов; быстрые действия; детали и Back; каталог и детали породы; сохранение при смене вкладок |
| G5 | Ошибки и восстановление на Android | Нет сети при запуске и в работе; таймаут; HTTP-ошибка; пустые/некорректные данные; нет породы; ошибка картинки; нет/неверный ключ; повтор без двойного лайка; уход с экрана во время запроса |
| G6 | Подмена API | Через `CAT_API_BASE_URL` все запросы идут к тестовому источнику, включая сценарии сбоев; вспомогательные данные тестов не входят в сдаваемое приложение |
| G7 | Визуальная проверка | Все четыре экрана, загрузки, ошибки, длинные тексты и узкий экран; нет переполнения; своя иконка; элементы имеют требуемые метки |
| G8 | Ревью кода и конфигурации | Ясно, кто хранит и меняет состояние; типизированные модели; сеть/JSON вне виджетов; корректный жизненный цикл; нет пустых `catch`, обхода TLS, лишних файлов/зависимостей; ключа нет в файлах и истории Git |
| G9 | Сдача | README из 8 разделов; авторское объяснение без ИИ; APK, тег Release, commit и медиа согласованы; доступ проверен из другого аккаунта/инкогнито; сборка воспроизводима без личного config-файла с переданными параметрами |

Не каждый gate применим к каждому промежуточному этапу. Перед сдачей обязательны все.
Настоящий ключ не вставляем в команды журнала, снимки экрана и вывод диагностики.
Если появятся тесты, их фактический запуск и результат тоже записываются.

## Ревью результата агента автором

наблюдаемое поведение, ожидаемый результат, исправление и повторную проверку.

для заполнения журнала не создаём. Самопроверка агента не заменяет ревью автора.
