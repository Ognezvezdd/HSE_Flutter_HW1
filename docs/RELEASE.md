# Предфинальный APK и публикация

Кандидат: `v1.0.0-rc.1`, версия приложения `1.0.0-rc.1+2`.
Локальный комплект находится в `build/releases/v1.0.0-rc.1/`:

- `cat-tinder-1.0.0-rc.1.apk` — обычный TheCatAPI, три ABI;
- `SHA256SUMS` — контрольная сумма;
- `release.json` — точный commit, версия, размер, ABI и SHA-256;
- `release-notes.md` — готовое описание.

Это не тестовый вариант с управляемым сервером. Настоящий ключ передаётся
при сборке из игнорируемого `config.json`; в исходники/журналы он не помещается.
Как и другие клиентские параметры, ключ в APK не является серверным секретом.

Публикация пока не выполнена: доступ к Git по SSH есть, но браузер GitHub
требует вход владельца для создания Release и загрузки файлов.

1. Открыть [создание Release](https://github.com/Ognezvezdd/HSE_Flutter_HW1/releases/new)
   под владельцем репозитория. Выбрать существующий тег `v1.0.0-rc.1`.
2. Заголовок: `Кототиндер 1.0.0-rc.1`; текст взять из `release-notes.md`.
3. Прикрепить APK, `SHA256SUMS` и `release.json`. Отметить **pre-release**.
4. После публикации добавить реальную прямую ссылку на APK в раздел 5 README.
   Проверить загрузку без входа в GitHub, установку и совпадение SHA-256.

Перед финальной сдачей автор повторно проверяет R1/R2 и заполняет раздел 7.
Если код меняется после кандидата, нужны новая версия/тег, APK и соответствующие
проверки/медиа. Ссылки на ещё не опубликованные файлы не используются.
