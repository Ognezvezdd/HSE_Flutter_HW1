# Финальный комплект и сдача

Версия приложения: `1.0.0+3`; тег: `v1.0.0`.
[Релиз](https://github.com/Ognezvezdd/HSE_Flutter_HW1/releases/tag/v1.0.0) ·
[прямая загрузка APK](https://github.com/Ognezvezdd/HSE_Flutter_HW1/releases/download/v1.0.0/cat-tinder-1.0.0.apk).
Локальная копия — `build/releases/v1.0.0/`:

- `cat-tinder-1.0.0.apk` — обычный TheCatAPI, универсальный APK;
- `SHA256SUMS` — контрольная сумма;
- `release.json` — точный commit, версия, размер, ABI и SHA-256;
- `release-notes.md` — описание релиза;
- `SUBMISSION.txt` — ссылки и SHA для сдачи.

APK использует конфигурацию из игнорируемого `config.json`, обычную проверку TLS
и локальную development-подпись. Тестовый API в эту сборку не входит. Ключ в APK
является клиентским параметром, а не защищённым серверным секретом.

## Что автор делает самостоятельно

1. **Заполняет раздел 7 README своими 5–10 предложениями, без ИИ.** Памятка для
   разбора — [ARCHITECTURE.md](ARCHITECTURE.md). Условие требует понимания решения.
2. **Скачивает APK из Release и лично проходит приёмочные сценарии:** коты,
   кнопки/свайпы, детали/Back, каталог, повтор после ошибки и сохранение.
   R1/R2 уже лично подтверждены автором 24.11.2026; агент не выдаёт свой прогон
   финального APK за авторский. Найденные проблемы записываются в журнал.
3. **Отправляет работу преподавателю** установленным в курсе способом: репозиторий,
   тег/commit и прямую ссылку APK из `SUBMISSION.txt`. Сначала убеждается, что
   собственный текст README закоммичен и отправлен в GitHub.

Если после релиза меняется исполняемый код, нужны новая версия/тег, APK и проверки.
Самостоятельный текст README можно добавить отдельным документирующим commit;
сдаваемый APK по-прежнему относится к точному commit, записанному в Release.
