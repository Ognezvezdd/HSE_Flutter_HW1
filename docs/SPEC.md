# Кототиндер — спецификация

Статус: исходный план до реализации; решения уточняются с автором по ходу работы.
Источник требований: https://georgfed.github.io/hse-flutter-course/assignments/hw1.html
Траектория: разработка с агентом; автор просматривает изменения и принимает результат.

## Границы и устройство

Четыре экрана: коты, детали кота, каталог пород, детали породы. Целевая платформа
сдачи — Android; Web используется для быстрой проверки, но не заменяет проверку APK.
Не входят: аккаунты, сервер приложения, история лайков. По замечанию автора R2
счётчик и текущий кот сохраняются локально между обновлениями страницы и запусками.
На первой установке счётчик равен нулю. Данные Web привязаны к origin браузера.

Модели `Cat` и `Breed` типизированы. HTTP-запросы, проверка ответа и разбор JSON
отделены от виджетов; источник данных настраивается в одном месте. Начальный подход
к состоянию — встроенные `State` и `setState`, передача данных через конструкторы,
действий — через callback. Отдельные слои и пакеты добавляются только по необходимости.

## Коты и действия

- Первый запуск: счётчик 0, видна загрузка; после получения данных и фотографии
  появляется карточка с названием породы. Фото и порода относятся к одному коту.
- Вправо и кнопка лайка вызывают один обработчик; влево и кнопка пропуска — другой.
  Одно принятое действие означает один переход к следующему коту.
- Лайк учитывается сразу, пропуск не меняет счётчик. После действия карточка
  становится недоступна для повторных действий и начинается загрузка следующей.
- Если загрузка следующего кота завершилась ошибкой, лайк сохраняется. «Повторить»
  повторяет только загрузку и не начисляет лайк. Это действует и после ошибки фото.
- На карточку без загруженного изображения нельзя поставить лайк или сделать пропуск;
  ошибка фото предлагает повторить загрузку изображения того же кота.

## Восстановление ленты (R2)

- `shared_preferences` / `SharedPreferencesAsync` хранит один JSON-снимок:
  версия формата, счётчик и текущий кот (ID, URL фото, сведения о породе).
  Ключ API и байты изображений не сохраняются. Пространство ключей учитывает URL API.
- При запуске сначала читаем снимок и проверяем доступ к API, затем загружаем
  фотографию сохранённого кота. Новый случайный кот при обычном refresh не запрашивается.
- Принятое действие сначала сохраняет новый счётчик и отсутствие текущего кота,
  затем начинается запрос следующего. Пока запись выполняется, действия блокируются.
  Перезапуск во время запроса восстанавливает счётчик и продолжает загрузку;
  уже обработанный кот не возвращается. Полученный кот сохраняется до показа карточки.
- Ошибка записи не считается принятым действием: следующий запрос не начинается;
  повтор записи использует тот же снимок и не удваивает лайк. Ошибка чтения не
  затирает данные нулями. Повреждённый формат можно сбросить только с подтверждением.
- Проверки: восстановление того же кота и счётчика, перезапуск во время загрузки,
  лайк/пропуск и повтор после ошибки записи, ошибки чтения и повреждённый JSON.

## Детали и вкладки

- Тап по готовой фотографии открывает детали с переданным текущим `Cat`:
  тем же изображением и полной доступной информацией о его породе.
  Новый случайный кот при открытии деталей не запрашивается.
- Экран деталей прокручивается. Общий блок сведений о породе используется также
  в деталях породы: описание, происхождение, темперамент, срок жизни, вес,
  доступные оценочные характеристики и другие содержательные сведения API.
  Технические поля JSON не показываются; отсутствующие значения — «Нет данных».
- Back закрывает детали. Текущий кот, счётчик и состояние каталога сохраняются.
- Переключение «Коты / Породы» сохраняет состояния обеих вкладок; начальный вариант
  — `IndexedStack`. Скрытая вкладка не начинает новую загрузку из-за переключения.

## Каталог пород

- При первом открытии вкладки используется каталог из успешной проверки доступа
  через `/breeds`; если он ещё не загружен, видна загрузка. Одновременные обращения
  используют один запрос; неуспешный результат не кешируется.
  Список сортируется по названию; каждая строка показывает название породы.
- Успешно загруженный список хранится в памяти на время работы приложения;
  повторное открытие вкладки не вызывает новый запрос.
- Тап по строке передаёт выбранный `Breed` в детали. В начале показаны название,
  описание и четыре основных поля: происхождение, темперамент, срок жизни,
  группа породы. Далее — вес, история, альтернативные названия, доступные оценки
  с обозначением шкалы, признаки и ссылки на источники. Недостающие основные поля
  обозначены «Нет данных»; отсутствующие дополнительные разделы не создаются.
- Back возвращает к тому же списку и позиции прокрутки. Ошибка списка показывает
  сообщение и повтор; она не сбрасывает кота или лайки. Пустой список имеет отдельное
  понятное сообщение с возможностью повторить запрос.

## Сеть, ошибки и конфигурация

Используем TheCatAPI: `/images/search` с `has_breeds=1` и `/breeds`, пакет `http`.
Ключ — `CAT_API_KEY`, базовый адрес — `CAT_API_BASE_URL` через `--dart-define` и
`String.fromEnvironment`; адрес по умолчанию `https://api.thecatapi.com/v1`.
Конкретные адреса не дублируются по экранам. Настоящие ключи не входят в Git.

Таймаут сетевого запроса — 10 секунд. Обрабатываем отсутствие и потерю сети,
HTTP-ошибки, пустые или некорректные данные, кота без породы, сбой изображения,
отсутствующий или неверный ключ. Сообщение предназначено пользователю,
без текста исключения; есть подходящий повтор без перезапуска приложения.
Не допускаются пустые `catch`, обход проверки TLS и переход API на HTTP.
После `await` состояние обновляется только у смонтированного виджета;
уход с экрана во время запроса не вызывает необработанных исключений.

## Приёмка и оформление

Основной сценарий: запуск → готовый кот → лайк/пропуск → следующий кот → детали → Back;
дополнительный: каталог → выбранная порода → Back → возврат к текущему коту.
Повторные быстрые действия не умножают лайки и переходы; ошибки и повторы сохраняют
счётчик и загруженный каталог. Проверки заранее перечислены в `QUALITY_GATES.md`.

Интерфейс на русском, названия пород и сведения API допускаются на языке источника.
Единые отступы и оформление, заметная обратная связь, аккуратные загрузки и ошибки,
прокрутка длинных деталей, узкий экран без обрезаний, собственная иконка.
Метки `Semantics(identifier: ...)` и соответствующие `Key`: `cat_card`,
`cat_breed_name`, `like_button`, `dislike_button`, `like_counter`, `breeds_tab`,
`retry_button`. Текст счётчика содержит число.

Сдача: репозиторий, точный commit SHA, GitHub Release с APK из этого commit,
актуальные скриншоты/видео с состоянием ошибки и README из восьми разделов задания.
Раздел README об устройстве приложения автор пишет своими словами без ИИ.

## Изменения решений

- Детали и каталог: общий виджет сведений о породе, `Navigator.push/pop`, верхний
  `TabBar` и `IndexedStack` без конкурирующего горизонтального свайпа вкладок.
  Лайки остаются видны на обеих вкладках. Каталог хранится в API-клиенте на время
  работы; экран сохраняет прокрутку. Старые снимки R2 читаются без сброса счётчика:
  новые поля необязательны, недостающие сведения сопоставляются по ID/уникальному
  имени с каталогом при наличии. Каталог и детали проверяются также при сбоях,
  переключении вкладок во время запроса и на узком экране.
- Актуальные сведения API: https://docs.thecatapi.com/docs/examples/breeds —
  бесплатный ключ может не возвращать числовые рейтинги. Их не выдумываем;
  четвёртое основное поле — группа породы, а оценки показываются при наличии.
- R2, ревью автора: после refresh исчезали лайки и менялся кот. Это соответствовало
  прежней границе «только память», но автор изменил ожидаемое поведение. Добавляем
  локальное восстановление по правилам выше; оно расширяет исходные требования ДЗ.
- R1, ревью автора: неверный ключ приводил к HTTP 200 с котом без породы,
  поэтому интерфейс ошибочно предлагал повтор. Перед первым запросом кота
  проверяем доступ к `/breeds` и сохраняем успешную проверку на время сессии.
  Если последующий кот пришёл без породы, проверяем доступ снова, чтобы различить
  отзыв ключа и дефект данных. 401/403 дают явную ошибку ключа без кнопки повтора;
  исправление параметров сборки требует полного перезапуска. Настоящий кот без
  породы при подтверждённом доступе остаётся повторяемой ошибкой данных.
- Первый срез: реальные карточки, загрузка фото, лайк/пропуск кнопками и свайпами,
  счётчик, ошибки и повтор. Детали и каталог добавляются следующими этапами;
  неработающих кнопок и вкладок в интерфейсе нет. API использует внедряемый
  HTTP-клиент; фото загружается штатным `NetworkImage` до включения действий.
  У CDN нет CORS-разрешения для чтения байтов браузером, поэтому для Web выбран
  `WebHtmlElementStrategy.prefer`; на нативных платформах работает обычная загрузка.
  Ключ API не передаётся серверу фотографий. В тестах внедряется `MemoryImage`.
  Запрашиваем JPEG/PNG. Без ключа или с маркером для его замены показываем
  инструкцию конфигурации; демо-данные и запасные источники не используются.
- Исходный план: лайк учитывается до загрузки следующего кота; повтор его не дублирует.
  Данные живут в памяти, детали получают выбранную модель, вкладки сохраняют состояние.
  На момент записи исходного плана реализация требований ещё не была начата.
